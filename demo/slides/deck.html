How it works

Two enforcement points. Egress is what holds.

① Request check (Tourniquet)
Refuses a request whose content orders data sent somewhere the user never named. Narrow on purpose: it reads words, so wording can slip past it.
② Default-deny egress
Decides on the destination, not the words. A guest list, not a lie detector: it holds against every non-allowlisted destination we tried.

Honest limits
  • A plain "send it to my URL" phrasing usually walks past the request check: it blocked only 1 of 22 in our test.
  • Data sent to an allowlisted host still passes; the egress guard doesn't read TLS.
  • Egress isn't scored on a corpus yet: it holds against every non-allowlisted destination we tried.
What holds
  • Default-deny egress decides on the destination, so rewording the request doesn't change it.

Who uses it, and who pays

Teams running agents they can't rebuild. A vendor agent, an open-source agent or a legacy internal one: you can't rewrite its prompts or tool code, but you can control its network.
  • User: the platform or AppSec engineer shipping an internal or customer-facing agent on an OpenAI-compatible API.
  • Budget holder: head of engineering or security at a mid-size software company shipping agents, with no enterprise AI detection-and-response budget yet.
  • Their blocker: "we can't ship this agent until security signs off on what it can send out."
  • Wedge: an egress sidecar for agent tool calls: one container that becomes the agent's only route out. No code or model changes.

Beat 9, part 2 of 3.

How we stand apart: classifiers ask whether text looks like an attack, and an attacker can reword it. We ask whether the user authorized the destination, and rewording doesn't change where the data goes. It's the secure web gateway model — a destination allowlist on egress — applied one layer down, to an agent's tool calls.

The SWG line is an analogy for what the egress guard is, not a claim it works because gateways work. Never say "better than" any of these.

Path to launch: observe first, then enforce

  1. Now, prototype: reverse proxy + egress guard against DVAA and our own OpsBot, scored corpus, working demo.
  2. Open-source sidecar: one compose file in front of any OpenAI-compatible agent. Design partners run it in observe mode. Exit test: a partner leaves it in block mode.
  3. Managed policy and alert routing (paid): hosted allowlists and a honeytoken registry, alerts routed to the tools a team already uses. Price comes from design partners, not a guess.
